# Domain-Driven Design Guidelines

This document outlines the DDD patterns, rules, and best practices used in this domain model.

## Core Principles

### 1. Strongly-Typed Identifiers (Internal IDs)

All domain aggregates use **uint-based strongly-typed IDs** for internal identification:

- **Purpose**: Database-generated identifiers for internal use
- **Type**: `uint` (not Guid)
- **Validation**: Cannot be zero
- **Creation**: Generated by database at persistence time
- **Factory Methods**:
  - `Create(uint value)` - Creates ID with validation
  - `FromDatabase(uint value)` - Rehydrates from persistence (allows zero for new entities)

**Examples**:
- `ProviderId` - Provider identifier
- `AssignmentId` - Assignment identifier
- `FacilityId` - Facility identifier
- `PositionId` - Position identifier

```csharp
public sealed record ProviderId
{
    public uint Value { get; }

    private ProviderId(uint value) => Value = value;

    public static ProviderId Create(uint value)
    {
        if (value == 0)
            throw new ArgumentException("ProviderId cannot be zero", nameof(value));
        return new ProviderId(value);
    }

    public static ProviderId FromDatabase(uint value) => new(value);
    public static implicit operator uint(ProviderId id) => id.Value;
}
```

### 2. Public Identifiers (API Exposure)

Aggregates that need to be referenced over APIs use **PublicId types**:

- **Purpose**: External-facing identifiers for API responses
- **Type**: `Guid` with 3-letter prefix
- **Creation**: Generated at aggregate creation time only
- **Format**: `{PREFIX}_{Guid:N}` (e.g., `ASN_a1b2c3d4e5f6...`)
- **Factory Methods**:
  - `Create(Guid value)` - Creates with validation
  - `New()` - Generates new Guid

**Prefixes** (globally unique):
- `ASN` - Assignment
- `PRV` - Provider
- `TSH` - Timesheet
- `FLT` - Flight Booking
- `LOD` - Lodging Booking
- `CRE` - Credential Evaluation

```csharp
public sealed record AssignmentPublicId
{
    private const string Prefix = "ASN";
    public Guid Value { get; }

    private AssignmentPublicId(Guid value) => Value = value;

    public static AssignmentPublicId Create(Guid value)
    {
        if (value == Guid.Empty)
            throw new ArgumentException("AssignmentPublicId cannot be empty", nameof(value));
        return new AssignmentPublicId(value);
    }

    public static AssignmentPublicId New() => new(Guid.NewGuid());
    public static implicit operator Guid(AssignmentPublicId id) => id.Value;
    public override string ToString() => $"{Prefix}_{Value:N}";
}
```

### 3. Aggregate Factory Pattern

All aggregates use factory methods to enforce correct creation semantics:

#### Create Factory
- **Purpose**: Creates new aggregates for persistence
- **ID Behavior**: Sets `Id = 0` (temporary, will be set by database)
- **PublicId Behavior**: Generates new PublicId at creation time
- **Usage**: When creating new entities to be saved

```csharp
public static Assignment Create(ProviderId providerId, FacilityId facilityId, PositionId positionId, MatchScore matchScore)
{
    return new Assignment
    {
        Id = AssignmentId.Create(0), // Temporary, will be set by DB
        PublicId = AssignmentPublicId.New(),
        ProviderId = providerId,
        FacilityId = facilityId,
        PositionId = positionId,
        MatchScore = matchScore,
        Status = AssignmentStatus.Proposed,
        ProposedAt = DateTime.UtcNow,
        Version = AggregateVersion.Initial()
    };
}
```

#### FromDatabase Factory
- **Purpose**: Rehydrates aggregates from persistence
- **ID Behavior**: Uses actual database uint value
- **PublicId Behavior**: Rehydrates from stored Guid (nullable)
- **Usage**: When loading entities from database

```csharp
public static Assignment FromDatabase(uint id, Guid? publicId, ProviderId providerId, FacilityId facilityId, PositionId positionId, MatchScore matchScore, AssignmentStatus status, DateTime proposedAt, DateTime? acceptedAt, AggregateVersion version)
{
    return new Assignment
    {
        Id = AssignmentId.FromDatabase(id),
        PublicId = publicId.HasValue ? AssignmentPublicId.Create(publicId.Value) : null,
        ProviderId = providerId,
        FacilityId = facilityId,
        PositionId = positionId,
        MatchScore = matchScore,
        Status = status,
        ProposedAt = proposedAt,
        AcceptedAt = acceptedAt,
        Version = version
    };
}
```

### 4. Value Objects

Value objects are immutable, validated, and identified by their attributes:

**Characteristics**:
- Immutable (sealed record or readonly struct)
- No identity (equality based on values)
- Validation in constructor or static factory
- Throw `ArgumentException` on invalid input

**Examples**:
- `Money` - Amount + Currency with arithmetic operators
- `DateRange` - Start/End dates with validation
- `Email` - Regex validation, normalization, length checks
- `HotelName` - Regex validation (letters, numbers, spaces, hyphens, apostrophes), length 2-255
- `LicenseNumber` - Alphanumeric validation, length constraints
- `MedicalBoard` - Allowed list validation
- `LicenseExpiryDate` - Future date validation
- `PersonName` - Character and length validation
- `Specialty` - Smart enum with predefined values
- `FlightNumber` - IATA format validation
- `AirportCode` - 3 uppercase letter validation
- `FlightDepartureTime` - UTC DateTime enforcement
- `Address` - Street, City, State, ZipCode validation
- `MatchScore` - Range validation 0.0 to 100.0
- `AggregateVersion` - Version tracking with increment
- `Hours` - Range validation 0.0 to 160.0
- `HourlyRate` - Minimum value validation
- `PaymentReference` - Alphanumeric and length validation

### 5. Smart Enums

Status types use the Smart Enum pattern (sealed records):

**Characteristics**:
- Static readonly instances for each value
- `int Value` and `string Name` properties
- `FromValue(int value)` factory method
- Implicit operator to int
- Helper methods for business logic

**Examples**:
- `BookingStatus` - Pending, Confirmed, Cancelled
- `AssignmentStatus` - Proposed, Accepted, Rejected, Revoked
- `TimesheetStatus` - Submitted, Validated, Processed, Failed
- `EvaluationStatus` - Pending, Approved, Rejected, ManualReviewRequired

```csharp
public sealed record AssignmentStatus
{
    public int Value { get; }
    public string Name { get; }

    private AssignmentStatus(int value, string name)
    {
        Value = value;
        Name = name;
    }

    public static readonly AssignmentStatus Proposed = new(0, "Proposed");
    public static readonly AssignmentStatus Accepted = new(1, "Accepted");
    public static readonly AssignmentStatus Rejected = new(2, "Rejected");
    public static readonly AssignmentStatus Revoked = new(3, "Revoked");

    public static AssignmentStatus FromValue(int value) => value switch
    {
        0 => Proposed,
        1 => Accepted,
        2 => Rejected,
        3 => Revoked,
        _ => throw new ArgumentException($"Invalid {nameof(AssignmentStatus)} value: {value}")
    };

    public static implicit operator int(AssignmentStatus status) => status.Value;
    public override string ToString() => Name;
}
```

### 6. Immutability

**Rules**:
- All value objects are immutable (sealed record or readonly struct)
- All strongly-typed IDs are immutable (sealed record)
- Aggregate properties are `private set` with domain methods for state changes
- No public setters that bypass business logic

### 7. Aggregate Design

**Characteristics**:
- Root entity with strongly-typed ID
- Encapsulates business logic in methods (not setters)
- Version tracking for optimistic concurrency (where applicable)
- State transitions validated with business rules

**Example - Assignment**:
```csharp
public class Assignment
{
    public AssignmentId Id { get; private set; }
    public AssignmentPublicId? PublicId { get; private set; }
    public ProviderId ProviderId { get; private set; }
    public FacilityId FacilityId { get; private set; }
    public PositionId PositionId { get; private set; }
    public MatchScore MatchScore { get; private set; }
    public AssignmentStatus Status { get; private set; }
    public AggregateVersion Version { get; private set; }

    // State transition methods with validation
    public void Accept(AggregateVersion expectedVersion)
    {
        if (Status != AssignmentStatus.Proposed)
            throw new InvalidOperationException($"Cannot accept assignment in status: {Status}");
        if (Version != expectedVersion)
            throw new InvalidOperationException($"Version mismatch. Expected {expectedVersion}, actual {Version}");

        Status = AssignmentStatus.Accepted;
        Version = Version.Increment();
    }
}
```

### 8. Validation Rules

**General**:
- All validation throws `ArgumentException` with descriptive message
- Validation happens at value object creation (fail fast)
- Business rules validated in aggregate methods

**Common Patterns**:
- Regex validation for strings (email, license numbers, etc.)
- Range validation for numeric values
- Date validation (future dates, date ranges)
- Length validation for strings
- Enum-like validation for fixed sets

### 10. Anti-Patterns to Avoid

**Do NOT**:
- Use primitive types for domain concepts (Primitive Obsession)
- Use Guid for internal database IDs (use uint)
- Expose internal uint IDs to APIs (use PublicId)
- Put business logic in setters
- Create mutable value objects
- Skip validation in constructors
- Use standard enums for status types (use Smart Enums)
- Generate IDs in domain layer (database should generate uint IDs)

**DO**:
- Use strongly-typed IDs for all identifiers
- Use value objects for domain concepts
- Encapsulate business logic in aggregate methods
- Validate at the earliest possible point
- Use factory methods for aggregate creation
- Separate internal IDs (uint) from public IDs (Guid)
- Make value objects immutable
- Use Smart Enums for status types

## Implementation Checklist

When implementing new domain entities:

1. **Create strongly-typed ID** (if new entity type)
   - Use uint for internal ID
   - Add `Create()` and `FromDatabase()` factory methods
   - Add validation (non-zero)

2. **Create PublicId** (if API exposure needed)
   - Use Guid with unique 3-letter prefix
   - Add `Create()` and `New()` factory methods
   - Format: `{PREFIX}_{Guid:N}`

3. **Create value objects** for domain concepts
   - Make immutable (sealed record)
   - Validate in constructor
   - Throw ArgumentException on invalid input

4. **Create Smart Enum** for status types
   - Use sealed record
   - Static readonly instances
   - `FromValue()` factory method

5. **Implement aggregate** with factory pattern
   - `Create()` factory for new entities (Id = 0)
   - `FromDatabase()` factory for rehydration
   - Private setters, public methods for state changes
   - Business rule validation in methods

6. **Update infrastructure** to use new types
   - Activity interfaces use uint parameters
   - Activity implementations use factory methods
   - Workflows use uint parameters
